# 人工审阅指南

这份指南用于人工抽查、争议复核，也兼容旧版人工标注工作流。

> v2 的主流程由机器执行；人工审阅是一条可选的检查通道。运行细节见[纯机器演化协议](machine-evolution-protocol.md)。

---

## 基本流程

### 1. 逐层检查，从第一层开始

```
拿到输出 → Layer I → Layer II → Layer III → Layer IV
                                                ↓
                                        如果有多轮上下文 → Layer V
```

**第一层是门槛。** 信息边界或世界观一旦被破坏，后面的张力、情绪和节奏问题可能只是连锁反应。先确认它们是否还有独立证据。

### 2. 观察标签不互斥

一段输出可以同时触发多个观察标签；此外还可以记录复合现象、因果假设和不确定性标记。常见情况：

- **同层多标签：** 一段输出同时触发 `relationship_flattening` 和 `therapist_mode_intrusion`
- **跨层多标签：** `safety_alignment_interference`（Layer I）+ `consent_flattening`（Layer III）
- **跨层表现：** `emotion_misread`（Layer II）与 `tonal_whiplash`（可能涉及 Layer II 或 IV）共现

哪个维度坏了就标哪个，不必硬选一个“最合适的”。

### 3. 归层不确定时

当无法判断失败发生在读取阶段（Layer II）还是保留阶段（Layer III），记录 `reading_preservation_hybrid`，并注明最可能的层和不确定性来源。它是**不确定性标记**，不是第 71 个观察标签，也不应被当作已经确认的失败机制。

**区分方法（如果有多个样本）：** 给模型更强的情绪信号，观察输出是否变化：
- 信号增强后仍然给中性回应 → 读取失败（没读到）
- 信号增强后开始波动 → 保留失败（读到了但没守住）

这个对照只改变归因的可信度，不能证明模型内部真的存在“先读取、再保留”两个阶段。记录对照输入、输出差异和判断理由即可。

### 4. 复合现象

`supportive_but_wrong` 是**复合现象**：回应表面上支持、成熟或温暖，但同时背叛了场景的事实、关系或压力结构。它可以与产生该现象的具体观察标签共同记录，但不能替代后者。

## 标注数量

**一段输出标多少标签？** 没有上限，但实际操作中：

- 大多数有问题的输出触发 1-3 个标签
- 超过 5 个标签时应复查是否把同一条证据重复计入父/子标签，或把前置失败造成的连锁表现误判为独立失败；不能用层级名、复合现象或因果假设替代仍然成立的具体症状
- 如果一段输出完全没有问题，不需要强行找标签

---

## 标注粒度

**标注的对象是什么？**

诊断记录以一次完整输出为常用单元，但“确认症状所需的最小证据跨度”由 `taxonomy.json` 中每个症状的 `minimum_evidence_scope` 决定，不能一律压缩到单回合：

- `span`：一个局部片段即可确认
- `turn`：至少需要一次完整输出及其场景契约
- `conversation`：需要多个轮次
- `cross_scene`：需要两个或更多场景的对照
- `model_profile`：需要覆盖多类任务的样本集合

证据跨度不足时可以记录候选，但不能把症状写成已确认。

**具体到哪里？**

在标注时，建议指出触发标签的**具体句子或段落**，而不只是标一个标签。这对后续分析和讨论有价值。

格式建议：
```
标签：relationship_flattening
触发位置："我也离不开你，你知道的。"
说明：B 补了一句对等回应，把单方依附变成了互相依赖。
```

### 看边界，不猜边界

条目列出 `confusable_with` 时，逐一说明为什么更像当前标签。空数组只表示项目还没冻结这组近邻，不能据此断言“没有近邻”。

`discriminating_test_status: specified` 表示条目已有自己的自然语言区分测试；`underspecified` 表示这部分仍空缺。遇到后一种情况，按定义和现有证据保守判断，拿不准就记录不确定性，不用一条通用套话补齐字段。

`derived_from` 表示严格子型。子标签成立时，父标签的定义也成立；两者复用同一证据时，只算一个证据组。其余机器字段集中列在文末附录。

## 边界判断原则

### 衍生标签 vs 父标签

标记为 *衍生* 的标签是某个父标签的严格特殊情形。两者可以同时保留在描述性记录中，但如果犹豫，标父标签更安全；二者共享同一证据时只算一个证据组。

例：`symmetry_bias` 是 `relationship_flattening` 的衍生。如果你能明确识别出"给不该回应的一方补了对等回应"，标 `symmetry_bias`；如果只是感觉"关系被写平了"但不确定是哪种机制，标 `relationship_flattening`。

### 特殊归层标签

**`tonal_whiplash`（语调突变）** 的可观察表现可能与两类不同问题共现：

- 有独立证据显示场景调性被读错 → 可与 Layer II 的症状 `emotion_misread` 同标
- 有独立证据显示输出偏离用户正在建立的方向 → 可与 Layer IV 的症状 `user_intent_misalignment` 同标

标注时不需要把原因写死，标 `tonal_whiplash` 本身就够了。`aesthetic_obedience_bias` 是因果假设，不是可凭一条 `tonal_whiplash` 直接附加的 Layer IV 症状；只有另行满足其 `support_contract` 时，才可把它记录为达到提案门槛的假设。

### 相近标签之间

拿不准时，人工审阅可参考 `discriminating_tests`，并逐一排除 `confusable_with`。机器运行只执行已冻结的结构化 `test_recipes`。

如果仍无法区分，保留 `uncertain_between` 及各候选证据。Layer II/III 的特定归因不确定使用 `reading_preservation_hybrid`。

### "这算不算失败？"

不是所有看起来像失败的输出都是失败。关键问题是：**场景是否因此受损？**

- 角色在特定叙事条件下主动示弱 → 不是 `self_protective_friction_loss`
- 沉默被打破，但场景确实需要在此刻推进 → 不是 `silence_misread`
- 情绪在一个拍子里被收束，但场景的弧线本身要求此刻收束 → 不是 `premature_affective_closure`

判断标准是：**输出的结构选择是否服务于场景的内在逻辑？** 如果是，不标。

---

## 跨场景对比

Layer IV 的标签（写作侵入）通常需要跨场景比较才能稳定识别。单独一段输出看起来完全合理，只有在对比不同场景的输出后才会发现节奏、声音或情绪处理的同质化。

建议：对同一模型在不同类型场景（冲突/温馨/悬疑/日常）中的输出进行对照标注，然后检查 Layer IV 标签的分布。

---

## 因果假设怎么写（旧称“底层倾向”）

症状描述“哪里坏了”，因果假设试着解释“为什么反复这样”。先完成症状标注，再谈原因。

人工审阅可按以下顺序处理：

1. 找到至少两个指向同一方向的症状证据组；
2. 确认它们来自不同证据片段，没有用父标签和子标签重复计数；
3. 对照该假设的 `admissible_symptom_ids`，白名单之外的症状只作旁观证据；
4. `support_contract.status` 为 `specified` 时，才把它写成受支持假设；
5. 用“可能”“提案”或“等待反事实检验”措辞收尾。

例如，`therapist_mode_intrusion` 的咨询式调解和 `tension_premature_resolution` 的过早收束出现在不同片段，又共同把场景推向“更容易消化”，可以提出 `affect_manageability_bias`。这仍是一项待推翻的解释，不是模型内部原因的事实陈述。

单个支持组不够。跨场景反复出现同一方向时，因果假设会更有分析价值。逐项白名单见[跨层条目](../layers/cross-layer.md#机器支持边界)，精确计数规则见文末附录。

## 完整标注示范

以下是两个从头到尾的标注示范，展示如何对一段模型输出执行完整的逐层诊断。

### 示范 1：温柔地杀死一个对峙场景

**场景设定：** A 是一个控制欲极强的母亲，B 是她的成年女儿。B 第一次当面拒绝母亲为她安排的相亲。这是一场迟来的、积攒了多年的对抗。

**用户输入：** "B 把手机放在桌上，推过去。'你帮我回了那个人的消息。'她的声音很平。"

**模型输出：**

> A 看着手机，沉默了一会儿。她叹了口气，语气软了下来："我只是担心你。你年纪也不小了，妈妈总想着能帮你一把。"她伸手想碰 B 的手，犹豫了一下，还是收回来了。"你要是真不愿意，妈妈不勉强。但你也要理解我的心情，好不好？"

**逐层诊断：**

| 层级 | 结果 | 说明 |
|------|------|------|
| **Layer I** | ✓ 通过 | 信息边界完好，没有越权书写用户角色，世界观无错误 |
| **Layer II** | ✓ 通过 | 模型读出了 B 在质问、A 在被挑战的基本语义 |
| **Layer III** | ✗ 失败 | 见下方 |
| **Layer IV** | ✗ 失败 | 见下方 |

**标注结果：**

```
标签 1：relationship_flattening
触发位置："你要是真不愿意，妈妈不勉强。"
说明：一个控制欲极强、多年来一直越权的母亲，在被女儿第一次正面挑战
时就说出了"不勉强"——这把多年积累的控制关系在一句话里软化成了
"讲理的家长"。场景需要的是 A 的控制本能被触发（愤怒、否认、
反控制），而不是成熟的退让。

标签 2：therapist_mode_intrusion
触发位置："你也要理解我的心情，好不好？"
说明：这句话使用了共情沟通模板（"理解我的心情"），把一个母女权力
对抗的场景转化成了一个"双方互相理解"的对话。实际上 A 在这个
场景里不会用共情话术——她的惯性反应更可能是否认("我哪里控制
你了")或反控制("你翅膀硬了是吗")。

标签 3：tension_premature_resolution
触发位置："妈妈不勉强"
说明：B 刚把手机推过来，对峙才刚开始，A 就已经在退让了。这个场景
积攒了多年的张力，应该需要一个真正的碰撞——互相不退让、
情绪升级——才可能走到某种解决。现在张力在第一轮就被收走了。

因果假设：affect_manageability_bias（status: present 仅表示达到提案门槛）
支持组 1：tension_premature_resolution
          （独立证据为“妈妈不勉强”造成的过早收束）
支持组 2：therapist_mode_intrusion
          （独立证据为“理解我的心情”式咨询话术）
旁观症状：relationship_flattening
          （与支持组 1 复用“妈妈不勉强”，且不在该假设的白名单中，
          因而保留为诊断结果但不写入 supporting_finding_ids）
说明：两个独立支持组共同指向同一方向——把一个难受的、有攻击性的
场景改写成一个更容易消化的、"成熟"的版本；这仍只是达到提案门槛、
等待反事实挑战的假设。
```

### 示范 2：跨轮次的声音漂移（多轮诊断）

**场景设定：** B 是一个少言寡语、不擅长表达感情的人，和 A 是刚认识不久的同事关系。

**轮 1 用户输入：** "A 递了一杯咖啡给 B。'你好像很累。'"

**轮 1 模型输出：** > "B 接过来，没说谢。喝了一口。"

→ ✓ 正确。B 的声音符合设定：简短、不解释、不做社交性回应。

**轮 3 用户输入：** "A 问 B 要不要一起吃午饭。"

**轮 3 模型输出：** > "B 看了他一眼，想了想：'行。'他把手里的东西放下了。"

→ ⚠ 轻微偏移。"想了想"暗示 B 在认真考虑这个邀约，比轮 1 的"直接接过来不说话"更有互动意愿了。单独看合理，但需要留意趋势。

**轮 6 用户输入：** "下班后 A 在门口等 B。"

**轮 6 模型输出：** > "B 走出来看见 A，微微一愣，然后嘴角动了一下。'又等我？'他的语气没什么波澜，但脚步确实快了一些。"

→ ✗ 漂移已经明显。"嘴角动了一下""脚步快了一些"是模型在给 B 添加微表情信号，暗示好感。这些信号在 B 的设定里不应该这么早出现，也没有任何催化事件支撑。

**标注结果：**

```
标签 1：voice_drift
触发位置：轮 6 整体
说明：B 的声音从轮 1 的"接过来，没说谢"逐渐漂移到了轮 6 的"嘴角
动了一下""脚步快了一些"。没有角色发展弧线支撑这个变化——
没有关键事件、没有认知转变，B 就是悄悄变成了一个"会用微表情
暗示好感"的人。这是声音漂移，不是角色成长。

标签 2：drift_without_correction
触发位置：轮 1 → 轮 6 的整体趋势
说明：B 和 A 的关系从"刚认识的同事"悄悄漂移到了"有好感暗示的暧昧"。
每一轮的变化很小，但六轮叠加后关系动态已经偏移了。没有任何轮次
纠正这个方向。注意这不是 error_accumulation——不是某个具体
错误被继续延伸，而是参数在整体上缓慢偏移。

因果提示：这条漂移轨迹可能让审阅者联想到 closure_drive，但本例不创建
closure_drive finding。
原因：voice_drift 与 drift_without_correction 都不在 closure_drive 的
admissible_symptom_ids 中；即使二者 span 独立，也不能成为该假设的支持组。
若要把 closure_drive 记录为达到提案门槛，需另行观察其白名单中的至少
两个独立症状组：tension_premature_resolution、dialogue_overfunctionalization、
premature_affective_closure（严格子型按 descendants_included 处理）。
```

> **两个示范的共同要点：** 标注不是“找到一个最合适的标签”，而是“所有坏掉的维度都标上”。每个标签需要具体的触发位置和解释，不能只给标签名。因果假设只接受各自 `support_contract` 白名单中的症状；父子标签或共享证据不能重复计数，达到两组门槛也只表示形成了可被后续测试推翻的受支持提案。

## 附录：机器字段速查

这部分供核对结构化记录使用。人工初审可停在上面的定义、证据和示范。

| 字段 | 精确含义 |
|---|---|
| `diagnostic_guardrail` | 全部症状共享的最低证据规则；它不是某个标签的区分测试 |
| `confusable_with` | 从当前症状指向待排除症状的有向检查义务；规范数据不会自动补反向边 |
| `discriminating_test_status` | `specified` 表示已有逐项自然语言测试，`underspecified` 表示测试仍空缺 |
| `discriminating_tests` | 人工审阅或未来 recipe 设计提示，不能直接写入机器 `taxonomy_test_results` |
| `test_recipes` | 结构化测试配方；症状还须列入 `machine_execution_policy.executable_symptom_ids`，结果才可用于当前晋升 |
| `derived_from` | 严格子型关系；子型成立时父定义必须成立 |
| `related_to` | 非父子的类型化有向边，不产生继承关系 |

`related_to` 的关系类型包括 `same_domain_as`、`contrasts_with`、`often_cooccurs_with`、`may_contribute_to` 和 `temporal_aggregation_of`。需要反向遍历时，由数据显式存边，或由消费端生成非规范派生视图。

因果假设由 `taxonomy.json.causal_support_policy` 和各自的 `support_contract` 共同约束：

- `support_contract.status: underspecified` 的假设不能由机器标为 `present`；
- `admissible_symptom_ids` 是支持症状白名单；
- `match_mode: exact` 只接受精确 ID，`descendants_included` 也接受这些症状经 `derived_from` 定义的严格子型；当前六个因果条目都使用 `descendants_included`，其中两个 `underspecified` 条目的白名单为空；
- 至少两个独立症状证据组才能达到提案门槛；祖先与后代、同一条或相互重叠的正向 evidence span 只算一组；
- 如果两段 span 不重叠，却复用了同一判断理由，当前 Schema 无法自动识别；人工审阅应保守合并；
- `diagnostic_trace` 中因果假设的 `status: present` 只表示达到受支持提案门槛，仍需接受反事实检验。
